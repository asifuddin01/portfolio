title: "Officina AI — an execution tracer for Python, C and Java, with a tutor that explains the trace"
summary: "Write a program, press Trace, and step through what it actually did — forwards and back, line by line, with every variable it changed, every condition and the values it compared, and every call and return. The trace comes from running the program, never from a model. Python runs under sys.settrace in a Web Worker, with each if, while and ternary rewritten so that its operands are recorded as the program computes them, once. C and Java have no settrace, so the program reports on itself: it is parsed with tree-sitter and tracing calls are inserted on the lines they belong to — insertions only, never a new line, so the compiler's messages still point at the reader's code — and then compiled here in the browser, by clang built to WebAssembly or by the Eclipse compiler on CheerpJ's JVM. The C runtime registers each variable's address as its declaration runs and reads memory back after every statement, so a function that changes its caller's array through a pointer shows it at the step it happened; pointers are named by what they point at, structs and enums are shown field by field, a variable not yet given a value shows as ?, and an index past an array, a division by zero or a NULL pointer stops the trace on the line that did it, where C itself would carry on into undefined behaviour. The Java runtime passes the locals the compiler agrees are assigned and reads objects by reflection, never by calling toString(). All three produce one step format, held in memory with a snapshot every 256 steps, so any step of a 50,000-step trace is shown in under a millisecond and nothing is run twice. A run stops at 50,000 steps, five seconds or 256 KB of output, and says so. A tutor — Qwen2.5 Coder 32B on Cloudflare Workers AI, reached through the site's own Worker — explains a step, answers a question about it or writes a program to trace; it is handed the recorded facts and told not to add to them, and the Worker, not the page, holds its instructions and a per-visitor rate limit. Every C and Java example is traced natively in CI and held to printing exactly what it prints untraced, and the Python tracer is checked step for step against native CPython."
cvSummary: "Execution tracer for Python, C and Java that runs in the browser (Pyodide, tree-sitter, clang in WebAssembly, the Eclipse compiler on CheerpJ, Cloudflare Workers AI). One step format for all three, checkpointed so any of 50,000 steps shows in under 1 ms. LLM tutor grounded in the recorded facts, behind a same-origin, rate-limited Worker. Every C and Java example traced natively in CI against its untraced output."
